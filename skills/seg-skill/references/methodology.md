# 《分割任务方法论》

阅读导航：系统定位 → 总框架 → 通用规则 → 合并规则体系 → 文档类型 → 生成流程 → 模板 → 评分 → 错误修正 → 自检清单。

使用约束：本文件中的字段、阈值和策略是按任务选择的候选，不是必须整套复制的配置。生成时同时执行 `rules.md` 中的字段用途检查、空间度量选择和公式解释规则；当前明确需求与既定接口优先。没有业务或接口用途的可选字段不生成，未被需求采用的策略不自动增加。

## 0. 系统定位

**所属系统：AI 视觉算法交付文档系统**  
**子系统：目标分割 / 分割检测融合 / 状态识别类算法需求文档**  
**模块定位：把像素级 mask 结果转成可配置、可开发、可测试、可验收的业务报警规则**

分割任务文档的核心不是“模型能分割什么”，而是：

```text
业务场景
→ 分割标签
→ ROI / polygon / 全图范围
→ mask / 连通域 / 面积 / 占比 / 空间关系
→ 过滤规则
→ 时间 / 帧数稳定机制
→ JSON 输出协议
→ 示例验证
→ 字段解释
→ 验收边界
```

从 Project Sources 看，柜门打开类任务会用 `cabinet_open` 与 `cabinet_close` 的 mask 膨胀、交集、长边差异、短边像素阈值来判断是否报警；铰链着地类任务会计算铰链与绞盘 / 机器座连通区域的面积占比；常闭门任务会结合 ROI、多门实例、人员遮挡过滤、灰度图过滤和 mask 输出；烟雾火焰任务则使用面积上下限、面积占比、`mask_output_path`、天空分割过滤等规则。柜门打开检测 铰链着地检测 闸门、常闭门堵塞 神思烟雾

# 1. 方法论总框架

## 1.1 分割任务文档的核心公式

```text
分割任务文档 =
业务问题定义
+ 分割标签体系
+ ROI / mask 作用范围
+ 连通域 / 面积 / 占比 / 几何关系
+ 报警条件
+ 不报警条件
+ 过滤条件
+ 时间 / 帧数稳定机制
+ 参数配置表
+ JSON 输出协议
+ 报警 / 不报警 / 过滤态示例
+ 字段解释
+ 验收边界说明
```

## 1.2 与检测任务文档的关系

检测任务文档通常围绕 **目标是否存在、是否进入 ROI、是否满足空间关系** 展开；分割任务文档进一步强调 **mask 像素级结果如何转成业务判断**。Project Sources 中已有检测任务方法论也将算法文档定义为“业务场景 → 检测标签 → 规则判定 → 参数配置 → 报警输出 → 示例验证 → 边界约束”，分割任务是在这个基础上增加 mask、连通域、面积占比、覆盖比例和分割后处理规则。目标检测文档方法论

# 2. 去重后的通用规则

## 2.1 总规则表

| 编号 | 通用规则 | 说明 |
|---|---|---|
| R1 | 先写业务场景，再写算法逻辑 | 不允许直接从标签或 JSON 开始 |
| R2 | 分割标签必须分角色 | 区分报警标签、辅助标签、过滤标签、统计标签 |
| R3 | 必须明确 ROI / polygon / 全图范围 | 说明 mask 在哪里生效，ROI 外是否参与判断 |
| R4 | 必须说明 mask 的使用方式 | 用于报警、可视化、线下测试，还是问题排查 |
| R5 | 必须定义连通域规则 | 多个区域是否独立判断，断裂区域是否合并 |
| R6 | 使用几何量时必须给出公式与符号解释 | 写清分子、分母、坐标尺度、实例处理和阈值方向，不只写“面积较大” |
| R7 | 面积过滤阈值按业务需要配置 | `min_area` / `max_area` 只在明确需要像素过滤时使用；随距离变化的包含/接触程度优先选择合适的比例 |
| R8 | 复杂状态必须有空间关系 | 例如相邻、包含、交集、IoU、覆盖比例 |
| R9 | 视频流任务必须有时间 / 帧数机制 | 用投票抑制单帧误报 |
| R10 | 必须区分 `algorithm_data` 与 `model_data` | 前者是业务结果，后者是模型结果 |
| R11 | 必须给出报警和不报警示例 | 复杂任务还要给过滤态、边界态、中间态 |
| R12 | 必须写字段详解 | 字段名、类型、默认值、单位、业务含义要一致 |
| R13 | 必须写误报过滤策略 | 如灰度图、天空、人员遮挡、小面积、异常形状 |
| R14 | 必须面向工程交付 | 文档必须能被开发、测试、实施、客户验收直接使用 |
| R15 | 每个参数和输出字段必须有具体用途 | 内部计算量不自动输出；无用途的可选 `area_ratio` 等字段不保留 |
| R16 | 单帧票与最终报警必须分开解释 | 定义符号、类型、记票分支及窗口分子分母，不把独立投票悄悄改成同帧条件取交集 |

# 3. 合并后的规则体系

## 3.1 业务定义规则

每个分割任务先回答 6 个问题：

| 问题 | 示例 |
|---|---|
| 监控什么区域？ | 门区域、吊机下方、烟雾监控区、机器座区域 |
| 分割什么对象？ | 门、铰链、烟雾、火焰、天空、绞盘、机器座 |
| 判断什么异常？ | 打开、掉落、着地、污染、覆盖异常、烟火出现 |
| 异常如何从 mask 体现？ | 面积变大、占比超阈值、区域相邻、覆盖不足 |
| 什么情况下不报警？ | ROI 外、面积过小、人员遮挡、天空误报、灰度图 |
| 如何验收？ | JSON 输出、mask 可视化、报警 / 不报警样例、阈值解释 |

标准句式：

```text
对【业务区域】进行实时监测，当【分割目标】在【ROI / 指定区域】内出现【面积占比异常 / 空间关系异常 / 状态变化异常】时，系统触发报警并上报处理。
```

---

## 3.2 标签体系规则

分割标签不能只列名称，必须说明每个标签在业务规则中的角色。

| 标签角色 | 作用 | 示例 |
|---|---|---|
| 报警标签 | 直接触发报警判断 | `fire`、`smoke_black`、`cabinet_open`、`hinges` |
| 状态标签 | 表示正常 / 异常状态 | `cabinet_close`、`door`、`no_door` |
| 辅助标签 | 参与空间关系或占比计算 | `winch`、`seat`、`machine_counter` |
| 过滤标签 | 用于误报过滤 | `sky`、`village`、`person`、`mist` |
| 背景标签 | 用于分割模型训练或默认类别 | `background` |
| 统计标签 | 用于数量、面积、行数统计 | 浮球行、污染区域、裂缝区域 |

标准写法：

```text
`cabinet_open`：报警标签，表示柜门打开区域；
`cabinet_close`：辅助状态标签，表示柜门关闭区域，用于与 `cabinet_open` 判断相邻关系和长边长度差异；
`person`：过滤标签，当人员与门 ROI 有交集时，用于过滤遮挡导致的误报。
```

## 3.3 ROI / polygon 规则

分割任务必须明确 ROI 的作用范围。

| 场景 | 规则 |
|---|---|
| 单 ROI | 所有分割结果只在该 ROI 内计算 |
| 多 ROI | 每个 polygon 独立计算，独立输出结果 |
| 全图 | 全图参与分割，但报警可受面积 / 过滤条件控制 |
| ROI 内报警 | 目标 mask 与 ROI 有交集或占比超过阈值才报警 |
| ROI 外报警 | 必须明确说明 ROI 外目标是否参与报警 |
| ROI 多实例 | 输出 `polygon_name` / `roi_name` / `coordinate` 保持实例对应 |

标准写法：

```text
当输入存在多个 `polygon_1` 实例时，每个 polygon 独立计算 `{target_class}` 的分割面积和面积占比；仅当某个 polygon 内的有效分割区域满足报警阈值时，该 polygon 对应目标进入 `target_info`。
```

---

## 3.4 mask 使用规则

mask 至少要说明 4 件事：

| 项目 | 说明 |
|---|---|
| mask 来源 | 来自分割模型输出 |
| mask 用途 | 报警计算 / 可视化 / 线下测试 / 问题排查 |
| mask 输出字段 | 通常在 `model_data.mask` 或 `model_data.objects[].mask` |
| mask 输出条件 | 例如 `mask_output_path` 非空时才输出 |

标准写法：

```text
`mask` 表示分割结果的保存路径，仅当配置中存在 `mask_output_path` 且路径非空时输出。mask 主要用于线下测试、可视化和问题排查，业务报警结果以 `algorithm_data.target_info` 为准。
```

烟雾文档中存在 mask 输出样式变更要求，例如输出四通道 RGBA 图片、背景透明、目标为指定颜色，这说明 mask 可视化规则也需要在文档中单独说明。神思烟雾

## 3.5 连通域规则

分割任务必须把连续像素区域转成可判断对象。

| 判断项 | 规则 |
|---|---|
| 连通域单位 | 一个连续 mask 区域视为一个候选目标 |
| 多连通域 | 分别计算面积、外接框、长短边、占比 |
| 小区域 | 小于 `min_area` 过滤 |
| 异常大区域 | 大于 `max_area` 过滤 |
| 断裂区域 | 需要明确是否合并 |
| 相邻区域 | 可用 dilation 后求交集判断 |

标准写法：

```text
对 `{seg_class}` 的 mask 结果进行连通域分析，每个连通区域独立计算像素面积、外接矩形、长边、短边和 ROI 占比。小于 `{min_area}` 或大于 `{max_area}` 的连通区域不参与报警判断。
```

## 3.6 面积与占比规则

分割任务的报警逻辑必须量化，不允许只写“面积较大”。

| 指标 | 公式 | 适用场景 |
|---|---|---|
| 像素面积 | `area = mask_pixel_count` | 烟雾、火焰、裂缝、小目标过滤 |
| ROI 占比 | `roi_ratio = target_area / roi_area` | 区域污染、门打开、覆盖异常 |
| 类间占比 | `target_area / (target_area + ref_area)` | 铰链与绞盘 / 机器座关系 |
| 覆盖比例 | `mask ∩ ROI / ROI` | 停车区域、区域覆盖 |
| 交并比 | `mask_a ∩ mask_b / mask_a ∪ mask_b` | 天空过滤、空间关系过滤 |
| 外接框面积 | `width * height` | OCR / 检测分割融合过滤 |

选择度量时先回答“谁的多少被覆盖”。若 A 是被判断的小目标有效框或 mask、B 是大目标 mask，包含程度应按 `area(A ∩ B) / area(A)` 计算，不能直接用 IoU、全图占比或绝对交集像素阈值。各度量必须解释零分母、逐实例/合并方式、比较符号，并用低于、等于、高于阈值的算例检查边界。像素噪声过滤可按需求使用绝对面积，但应说明坐标尺度与用途。

标准写法：

```text
对 ROI 内 `{target_class}` 的有效 mask 面积进行统计：

`roi_ratio = target_area / roi_area`

当 `roi_ratio >= {ratio_thresh}` 时，认为当前 ROI 满足报警候选条件。
```

铰链着地文档中的报警条件就是典型类间面积占比：铰链连通区域像素值 / 铰链与绞盘或机器座连通区域像素值之和，大于阈值后报警。铰链着地检测

## 3.7 空间关系规则

当业务异常不是单个 mask 面积，而是多个对象之间的关系时，必须写空间关系。

逐实例关系先按目标对计算，再说明任一、全部或最大值等聚合方式；统计总覆盖面积才按需要用并集去重。不得把多个不满足接触条件的实例合并成满足的实例。不同距离下目标像素面积变化时，应按业务使用相对比例，具体阈值不能照搬历史案例。

| 关系 | 计算方式 | 示例 |
|---|---|---|
| 相邻 | mask 膨胀后求交集 | 柜门打开与柜门关闭区域相邻 |
| 包含 | A mask 是否在 B ROI / mask 内 | 铰链在机器座区域 |
| 覆盖 | A mask 覆盖 B 的比例 | 目标占位异常 |
| 交集 | `mask_a ∩ mask_b` | 烟雾与天空过滤 |
| IoU | `intersection / union` | 云误报烟雾过滤 |
| 距离 | 连通域中心点距离 | 多目标关系判断 |
| 长短边 | 外接矩形长边 / 短边 | 门打开、裂缝、条状物 |

标准写法：

```text
对 `{class_a}` 与 `{class_b}` 的 mask 分别进行连通域分析；将 `{class_a}` 的 mask 进行 dilation 后与 `{class_b}` 的 mask 求交集。若交集面积大于 0，则认为两者相邻，满足条件 1。
```

柜门打开文档中，报警条件包含：`cabinet_open` 与 `cabinet_close` 分割区域相邻、长边长度差异小于 30%、`cabinet_open` 短边像素值大于阈值，是典型“空间关系 + 几何约束 + 阈值”组合规则。柜门打开检测

## 3.8 过滤规则

分割任务的过滤规则必须写清楚“误报来源 → 过滤字段 → 过滤逻辑”。

| 误报来源 | 过滤策略 | 字段示例 |
|---|---|---|
| 小面积噪声 | 小于最小面积过滤 | `min_area` |
| 异常大区域 | 大于最大面积过滤 | `max_area` |
| 灰度图误判 | 灰度图跳过推理或切换模型 | `used_filter_gray` |
| 云误报烟雾 | 天空分割与烟雾 IoU 过滤 | `used_skyfilter`、`sky_iou` |
| 村庄 / 背景误报 | 背景类分割过滤 | `village_iou`、`village_min_area` |
| 人员遮挡 | person 与 ROI / mask 交集过滤 | `used_person_filter` |
| 形态异常 | 长宽比、长短边过滤 | `length_multiple_width`、`pilex_thresh` |
| 低置信度 | 检测 / 分割阈值过滤 | `thresh`、`mask_thresh` |
| 非业务区域 | ROI 外目标过滤 | `polygon_name`、`roi_ratio` |

标准写法：

```text
当 `used_skyfilter=true` 时，使用 `sky` 分割结果对烟雾候选目标进行过滤；若 `{smoke_class}` 与 `sky` 的 IoU 大于 `sky_iou`，则认为该目标为云 / 天空误报，不进入 `target_info`。
```

烟雾文档明确通过天空分割子模型和 `sky_iou` 过滤云朵误报，这类规则应沉淀为“辅助分割标签过滤主报警标签”的通用方法。神思烟雾

## 3.9 时序机制规则

视频流分割任务默认需要考虑时序稳定。

任何单帧票公式都要在首次出现时解释符号的业务含义、类型、取值、索引和作用范围，区分配置参数与计算结果。说明当前帧为何记 1/0/未知、每帧最多票数，以及如何进入多帧窗口。单帧票表达证据，多帧投票提供稳定性；分别投票后组合与同帧条件取交集后投票不等价，不能擅自替换。具体对比和算例见 `rules.md` 的“公式与单帧异常票必须可解释”。

| 类型 | 字段 | 说明 |
|---|---|---|
| 帧数投票 | `used_frame_switch`、`alert_frame_thresh`、`alert_frame_ratio` | 在固定帧窗口内统计赞同票 |
| 时间投票 | `used_time_switch`、`alert_time_thresh`、`alert_time_ratio` | 在固定时间窗口内统计赞同票 |
| 事件周期 | `frame_array`、`conditions`、`recover_frame_thresh` | 状态开始、持续、恢复 |
| 强制报警 | `must_alert_mode` | 特殊场景下绕过部分过滤 |
| 测试模式 | `used_test_mode` | 输出更多中间结果便于调试 |

标准写法：

```text
当 `used_frame_switch=true` 时，开启连续帧投票逻辑。`alert_frame_thresh` 表示投票窗口长度，单位为帧；`alert_frame_ratio` 表示赞同票比例阈值。当窗口内满足报警候选条件的帧数 / 窗口长度 ≥ `alert_frame_ratio` 时，当前帧触发报警。
```

## 3.10 JSON 输出规则

必须坚持双层结构：

```text
algorithm_data：业务判定结果
model_data：模型输出结果
```

| 字段 | 位置 | 作用 |
|---|---|---|
| `is_alert` | `algorithm_data` | 是否报警 |
| `target_count` | `algorithm_data` | 报警目标数量 |
| `target_info` | `algorithm_data` | 只放触发报警的目标 |
| `used_*` | `algorithm_data` | 配置开关回显 |
| `*_thresh` / `*_ratio` | `algorithm_data` | 阈值回显 |
| `mask` | `model_data` | mask 保存路径 |
| `objects` | `model_data` | 模型原始或后处理输出 |
| `area` / 业务所需比例字段 | 按既定接口放置 | 可选；仅在实际判定、明确展示/集成需求或必填协议使用时输出，比例须明确分母 |
| `conditions` | 两者可有 | 满足的报警条件列表 |

标准原则：

```text
target_info 只输出引发报警的业务目标；
model_data.objects 可以输出所有模型识别目标，包括未报警目标、过滤目标和辅助标签。
```

所有参数和输出字段均须能回答“谁使用、在哪条规则或哪项接口中使用、删除会影响什么”。`area_ratio` 不因分割任务或模板出现过就成为必备字段；没有明确用途时删除。既定接口必填字段保留并解释接口作用，内部计算量不自动扩展输出协议。

# 4. 通用规则与特定文档类型规则

## 4.1 通用规则

这些规则适用于所有分割任务文档。

| 模块 | 通用规则 |
|---|---|
| 业务场景 | 必须先说明监控对象、监控区域、异常状态 |
| 标签体系 | 必须说明每个分割标签的业务角色 |
| ROI 规则 | 必须说明全图、ROI 内、ROI 外、多 polygon 的关系 |
| mask 规则 | 必须说明 mask 是否输出、输出到哪里、用于什么 |
| 连通域 | 必须说明是否按连通区域统计 |
| 面积阈值 | 仅在需要时设置 `min_area` / `max_area`，说明单位、尺度与过滤目的 |
| 占比阈值 | 按业务选分母，说明零分母、实例聚合、阈值方向与等号边界 |
| 空间关系 | 多对象关系必须说明计算方式 |
| 过滤策略 | 必须说明误报来源与过滤逻辑 |
| 时序机制 | 监控场景必须说明连续帧 / 时间投票 |
| JSON | 必须区分业务结果和模型结果 |
| 示例 | 必须给报警、不报警，复杂任务给过滤态 |
| 字段解释 | 必须逐字段说明类型、默认值、含义、单位 |
| 验收边界 | 必须说明遮挡、光照、灰度图、断连、小目标等问题 |

---

## 4.2 特定文档类型规则

### A. 区域占比型分割文档

适用：污染、积水、烟雾、火焰、覆盖异常、门打开程度。

核心规则：

```text
报警 = ROI 内目标 mask 面积占比 ≥ 阈值
```

字段候选（仅保留本任务实际需要的项，计算量是否输出另按用途和协议决定）：

| 字段 | 作用 |
|---|---|
| `target_min_area` | 可选的目标最小有效面积过滤 |
| `target_max_area` | 可选的目标最大有效面积过滤 |
| `target_alert_area` / `mask_thresh` | 面积占比报警阈值 |
| `area_ratio` / `roi_ratio` | 参与业务判断的实际面积占比；明确分母，按输出用途选择是否回传 |
| `mask` | 分割结果路径 |
| `warning_list` | 报警类别列表 |

模板：

```text
对 ROI 内 `{target_class}` 的 mask 结果进行统计，计算有效分割面积与 ROI 面积的比例 `roi_ratio`。当 `roi_ratio >= {mask_thresh}`，且目标面积位于 [`{min_area}`, `{max_area}`] 范围内时，当前帧进入报警候选逻辑。
```

---

### B. 连通域关系型分割文档

适用：铰链着地、设备部件异常、结构件脱落。

核心规则：

```text
报警 = 目标连通域与参考连通域的面积关系 / 空间关系满足阈值
```

必备字段：

| 字段 | 作用 |
|---|---|
| `target_class` | 报警目标 |
| `ref_class` | 参考结构 |
| `target_area` | 目标连通域面积 |
| `ref_area` | 参考区域面积 |
| `target_ratio` | 目标 / 参考组合占比 |
| `winch_ratios` / `seat_ratios` | 业务阈值 |

模板：

```text
对 `{target_class}` 与 `{ref_class}` 的连通区域分别统计像素面积，计算 `{target_class}` 在组合区域中的面积占比：

`target_ratio = target_area / (target_area + ref_area)`

当 `target_ratio >= {ratio_thresh}` 时，认为 `{target_class}` 与 `{ref_class}` 存在异常接触 / 异常着地关系，触发报警。
```

---

### C. 状态变化型分割文档

适用：柜门打开、常闭门打开、卷帘门打开、设备开合状态。

核心规则：

```text
报警 = 状态标签变化 + 面积 / 几何关系满足阈值 + 持续时间满足阈值
```

必备字段：

| 字段 | 作用 |
|---|---|
| `open_class` | 打开状态标签 |
| `close_class` | 关闭状态标签 |
| `open_thresh` / `pilex_thresh` | 打开面积或短边阈值 |
| `alert_conditions` | 当前满足的条件 |
| `used_person_filter` | 人员遮挡过滤 |
| `used_time_switch` | 时间报警开关 |
| `used_frame_switch` | 帧数报警开关 |

模板：

```text
当前帧报警需要同时满足：

1. `{open_class}` 与 `{close_class}` 的分割区域相邻；
2. `{open_class}` 与 `{close_class}` 的长边长度差异小于 `{long_side_diff_thresh}`；
3. `{open_class}` 的短边像素值大于 `{short_side_thresh}`；
4. 若启用人员遮挡过滤，则 person 与 ROI 存在交集时不报警；
5. 若启用时间 / 帧数投票，则满足投票阈值后才报警。
```

---

### D. 过滤增强型分割文档

适用：烟雾火焰、灰度图、天空云朵、反光、背景误报。

核心规则：

```text
报警 = 主分割标签满足报警条件
- 被过滤标签 / 图像质量 / 辅助模型命中的误报
```

必备字段：

| 字段 | 作用 |
|---|---|
| `used_skyfilter` | 是否启用天空过滤 |
| `sky_iou` | 天空与报警目标 IoU 阈值 |
| `used_filter_gray` | 是否启用灰度图过滤 |
| `filter_class_switch` | 是否启用分类过滤 |
| `filter_class_thresh` | 分类过滤阈值 |
| `village_min_area` / `village_max_area` | 背景过滤面积阈值 |

模板：

```text
当 `{target_class}` 满足面积与占比报警条件后，继续执行过滤逻辑：

- 若 `used_filter_gray=true` 且当前帧为灰度图，则跳过当前帧报警；
- 若 `used_skyfilter=true` 且 `{target_class}` 与 `sky` 的 IoU 大于 `sky_iou`，则过滤该目标；
- 若目标面积小于 `{target_min_area}` 或大于 `{target_max_area}`，则过滤该目标。
```

---

### E. 检测 + 分割融合型文档

适用：离心机打开、门打开、烟火检测、设备状态识别。

核心规则：

```text
报警 = 检测目标存在 + 分割区域满足面积 / 占比 / 状态条件
```

必备字段：

| 字段 | 作用 |
|---|---|
| `thresh` | 检测置信度阈值 |
| `mask_thresh` | 分割面积占比阈值 |
| `warning_list` | 报警类别 |
| `model_data.objects` | 检测 / 分割模型结果 |
| `target_info` | 满足融合规则的报警目标 |

模板：

```text
当前帧报警需要同时满足：

1. 检测模型输出 `{det_class}`，且置信度大于 `{thresh}`；
2. 分割模型输出 `{seg_class}`，且 ROI 内面积占比大于 `{mask_thresh}`；
3. `{seg_class}` 属于 `warning_list`；
4. 满足时间 / 帧数投票条件后，触发报警。
```

# 5. 可直接执行的生成流程

## Step 1：识别任务类型

先判断任务属于哪一类：

```text
区域占比型？
连通域关系型？
状态变化型？
过滤增强型？
检测 + 分割融合型？
分割后统计型？
```

若一个任务同时满足多类，按主报警逻辑确定主类型，其他逻辑作为辅助模块。

---

## Step 2：抽象业务事件

填写：

```text
业务区域：
监管对象：
异常状态：
报警目的：
不报警条件：
特殊过滤条件：
验收重点：
```

示例：

```text
业务区域：常闭门 ROI 区域
监管对象：常闭门 / 卷帘门
异常状态：门长时间打开
报警目的：发现消防门未关闭风险
不报警条件：人员遮挡、ROI 外目标、打开时间不足
特殊过滤条件：灰度图过滤、person 与 ROI 交集过滤
验收重点：打开面积占比、持续时间、报警 JSON 是否正确
```

---

## Step 3：设计标签体系

输出标签表：

| 标签名 | 中文含义 | 类型 | 业务角色 | 是否参与报警 |
|---|---|---|---|---|
| `{class_a}` | `{中文名}` | mask | 报警标签 | 是 |
| `{class_b}` | `{中文名}` | mask | 辅助标签 | 否，参与关系判断 |
| `{class_c}` | `{中文名}` | 2D box | 过滤标签 | 否，参与过滤 |

---

## Step 4：定义 ROI / mask 作用范围

必须写清：

```text
1. 是否必须配置 ROI；

4. mask 是否只在 ROI 内计算；
5. 输出结果是否带 `polygon_name` / `coordinate`。
```

---

## Step 5：设计分割后处理规则

至少定义：

```text
1. 是否进行连通域分析；
2. 连通域是否独立输出；
3. 是否合并断裂区域；
4. 是否计算外接框；
5. 是否计算面积、长边、短边、面积占比；
6. 是否做膨胀、腐蚀、交集、IoU。
```

---

## Step 6：设计报警规则

用条件列表表达：

```text
报警条件：
1. 条件 A：目标 mask 面积满足阈值；
2. 条件 B：目标 mask 与 ROI 占比满足阈值；
3. 条件 C：目标 mask 与辅助 mask 满足空间关系；
4. 条件 D：目标未被过滤；
5. 条件 E：时间 / 帧数投票满足阈值。
```

并明确关系：

```text
最终报警 = 条件 A AND 条件 B AND 条件 C AND 条件 D AND 条件 E
```

或：

```text
最终报警 = 条件 A OR 条件 B
```

不能省略 AND / OR。

条件列表只保留本任务采用的项，不能机械串联所有候选策略。公式中的字母首次出现即定义；涉及单帧票时给出自然语言含义、记票分支与窗口算例，并核对事件确认和异常判断是否要求同帧发生。

格式：

```text

过滤字段：
过滤公式：
过滤后输出：
```

示例：

```text
过滤对象：天空中的烟雾候选区域
过滤原因：云朵容易误识别为烟雾
过滤字段：`used_skyfilter`、`sky_iou`

```

# 8. 错误示例与修正方式

## 错误 1：只写“识别到目标就报警”

### 低质量写法

```text
识别到烟雾就报警。
```

### 问题

没有说明：

```text
烟雾面积多大报警？
是否在 ROI 内？
是否过滤天空 / 云？
是否需要持续时间？
是否输出 mask？
```

### 修正写法

```text
对 ROI 内 `smoke_black`、`smoke_white`、`smoke_yellow` 的 mask 结果进行连通域分析，过滤面积小于 `smoke_min_area` 或大于 `smoke_max_area` 的区域；当有效烟雾区域面积占比大于 `smoke_alert_area`，且未被 `sky_iou` 天空过滤规则命中时，当前帧进入报警候选逻辑。若 `used_time_switch=true`，需满足时间投票阈值后触发报警。
```

---

## 错误 2：面积占比公式不清楚

### 低质量写法

```text
铰链面积占比大于阈值时报警。
```

### 问题

不知道分母是什么：

```text
铰链面积 / 全图？
铰链面积 / ROI？
铰链面积 / 铰链 + 绞盘？
铰链面积 / 机器座？
```

### 修正写法

```text
当铰链连通区域出现在绞盘连通区域之间时，计算：

`in_winch = hinges_area / (hinges_area + winch_area)`

当 `in_winch >= winch_ratios` 时，认为铰链与绞盘区域存在异常接触关系，触发报警。
```

---

## 错误 3：空间关系不可计算

### 低质量写法

```text
柜门打开区域和关闭区域靠得比较近时报警。
```

### 问题

“靠得比较近”无法开发和测试。

### 修正写法

```text
对 `cabinet_open` 与 `cabinet_close` 的 mask 分别进行连通域分析；将两个 mask 进行 dilation 后求交集，若交集面积大于 0，则认为两者相邻，满足条件 1。
```

---

## 错误 4：过滤规则只有名称，没有逻辑

### 低质量写法

```text
支持天空过滤。
```

### 问题

不知道什么时候过滤。

### 修正写法

```text
当 `used_skyfilter=true` 时，使用 `sky` 分割结果对烟雾候选区域进行过滤。若 `IoU(smoke, sky) > sky_iou`，则认为该烟雾候选为天空云朵误报，不进入 `target_info`。
```

---

## 错误 5：JSON 中业务结果和模型结果混在一起

### 低质量写法

```json
{
  "is_alert": true,
  "objects": [
    {
      "name": "smoke",
      "area": 1234
    }
  ]
}
```

### 问题

无法区分：

```text
哪些目标报警？
哪些目标只是模型识别结果？
配置参数在哪里？
mask 在哪里？
```

### 修正写法

```json
{
  "algorithm_data": {
    "is_alert": true,
    "target_count": 1,
    "target_info": [
      {
        "name": "smoke_black",
        "area": 1234
      }
    ]
  },
  "model_data": {
    "mask": "/path/to/mask_result.png",
    "objects": [
      {
        "name": "smoke_black",
        "area": 1234
      }
    ]
  }
}
```

---

## 错误 6：字段没有单位

### 低质量写法

```text
alert_time_thresh：报警阈值。
min_area：最小面积。
```

### 问题

不知道时间单位和面积单位。

### 修正写法

```text
`alert_time_thresh`：int，单位为秒，表示时间投票窗口长度。
`min_area`：int，单位为像素，表示单个有效连通区域的最小面积，小于该值的区域不参与报警判断。
```

---

## 错误 7：没有不报警条件

### 低质量写法

```text
当门打开时报警。
```

### 问题

测试和客户会追问：

```text
人员遮挡算不算打开？
打开一瞬间算不算？
ROI 外打开算不算？
灰度图是否报警？
```

### 修正写法

```text
以下情况不报警：

1. `open_area` 面积占比小于 `open_thresh`；
2. 人员 `person` 与门 ROI 存在交集，认为可能由遮挡导致；
3. 打开状态未持续达到 `alert_time_thresh`；
4. 当前帧为灰度图且 `used_filter_gray=true`；
5. 目标位于 ROI 外。
```

# 9. 后续生成文档时必须遵守的规则清单

## 9.1 总规则

```text
1. 必须先写业务场景，再写算法逻辑。
2. 必须说明任务属于哪种分割类型：区域占比型、连通域关系型、状态变化型、过滤增强型、检测分割融合型。
3. 必须列出分割标签，并说明每个标签的业务角色。
4. 必须说明 ROI / polygon / 全图的作用范围。
5. 必须说明 mask 是否输出、输出位置、使用目的。
6. 必须说明是否做连通域分析。
7. 使用面积时必须说明计算公式与坐标尺度。
8. 使用比例时必须按业务选分母，说明公式、零分母和实例聚合方式。
9. 按需求使用面积阈值时必须说明单位、尺度和过滤方向，不能自动添加面积上下限。
10. 必须说明空间关系的计算方式，不能使用“靠近”“相邻”“覆盖较多”等模糊词。
11. 必须说明报警条件之间是 AND 还是 OR。
12. 必须说明不报警条件。
13. 必须说明过滤规则及触发条件。
14. 视频流任务必须说明时间 / 帧数投票机制。
15. 必须提供自定义参数表。
16. 参数表必须包含字段名、类型、默认值、单位、说明。
17. 必须使用 `algorithm_data` / `model_data` 双层 JSON 结构。
18. `target_info` 只放触发报警的目标。
19. `model_data.objects` 可放模型识别到的全部目标。
20. 必须提供报警、不报警示例。
21. 复杂任务必须提供过滤态或边界态示例。
22. 必须提供字段详解。
23. 必须说明可视化规则。
24. 必须说明验收边界和现场调参项。
25. 不允许只写“识别到目标就报警”。
26. 参数和输出字段必须有具体用途或明确接口要求，删除无用途的可选字段。
27. 公式首次出现时定义所有符号的业务含义、类型、取值和作用范围，区分计算量与配置参数。
28. 单帧票必须解释计票目的与分支、窗口分子分母及最终报警，不能擅自改变同帧门控。
29. 历史案例阈值不自动迁移；用小于、等于、大于阈值的算例核验比较符号。
```

## 9.2 分割专属规则

```text
1. mask 必须说明来源、用途和输出字段。
2. 连通域必须说明是否独立判断、是否合并断裂区域。
3. 面积必须说明是像素面积，不得写成抽象面积。
4. 面积占比必须说明分子和分母。
5. 多 ROI 场景必须说明每个 ROI 独立计算。
6. 辅助分割标签必须说明如何参与过滤或空间关系判断。
7. 过滤标签不得进入报警 target_info，除非其本身也是报警目标。
8. 若使用 IoU、交集、膨胀、腐蚀，必须说明计算对象。
9. 若使用长边 / 短边，必须说明来自外接矩形还是 mask 轮廓。
10. 若输出 mask 图片，必须说明图片格式、透明度、颜色规则和输出路径。
```

## 9.3 JSON 专属规则

```text
1. `is_alert=true` 时，通常 `target_info` 不能为空。
2. `is_alert=false` 时，通常 `target_info=[]`。
3. `target_count` 必须等于 `target_info` 数量。
4. `algorithm_data` 中放业务判断结果和参数回显。
5. `model_data` 中放模型输出、mask、objects。
6. 字段命名必须前后一致，不能一处写 `objects`，一处写 `object_data`，除非兼容旧协议并明确说明。
7. 示例 JSON 必须合法，不能有中文逗号、重复 key、缺少括号。
8. 字段解释必须与 JSON 示例一致。
9. `area_ratio` 等可选字段只在实际业务或明确接口需要时输出，内部计算量不自动回传。
```


# 最终结论

**《分割任务方法论》的核心结论是：分割任务文档不是“mask 输出说明”，而是“像素级结果到业务报警规则的转换说明”。**

后续所有分割任务文档都必须遵循：

```text
业务异常
→ 分割标签
→ ROI / mask 范围
→ 连通域
→ 面积 / 占比 / 空间关系
→ 过滤规则
→ 时序机制
→ JSON 输出
→ 示例验证
→ 字段解释
```

最重要的生成原则是：

> **不要写“识别到目标就报警”，而要写清楚“什么 mask，在什么区域，按什么公式，超过什么阈值，经过哪些过滤，持续多久之后，才进入报警输出”。**
